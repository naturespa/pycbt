# 他校で pycbt を使うための導入・運用ガイド

このガイドは、[pycbt の公開コード](https://github.com/naturespa/pycbt)をもとに、自校の問題・名簿・成績管理で CBT を動かす先生向けです。公開ページは問題を表示する場所、先生PCは成績を受け取る場所です。初めて導入する場合の流れと、試験ごとの運用を一続きにまとめています。

> **先に確認**：現在の問題・正答データは公開リポジトリに含まれ、GitHub Pages から読めます。秘密にしたい本番問題を、この構成のまま置かないでください。受験番号と氏名は自己申告であり、本人確認にはなりません。学校のネットワークで「公開ページから先生PCの 3000 番ポートへ通信できるか」を必ず実機で試してください。

## 1. 全体像と必要なもの

| 場所 | 役割 | 主なファイル・データ |
| --- | --- | --- |
| GitHub Pages | 生徒に問題を表示 | `index.html`、`app.js`、問題プールなど。公開される領域 |
| 生徒のブラウザ | 解答・結果の一時保存、先生PCへ提出 | 受験番号・氏名・先生PCのIPを入力。受験中のデータはその端末内 |
| 先生PCの `C:\cbt` | 受信、サーバ側再採点、管理画面 | `server.js`、`admin.html`、`scoring.js`、`answer-key.json` |
| 先生PCの `C:\cbt` | 成績・名簿・バックアップの保管 | `pycbt.db`、`meibo.csv`、`backups\`。GitHubへアップしない |

用意するものは、GitHubアカウント、Node.js と npm が動く先生PC、同じ校内ネットワークにつながる生徒端末です。先生PCは試験中に起動し続けます。ソフトの追加や受信ポートの設定は学校の端末・ネットワーク運用に合わせて行ってください。

このコードの初期設定は **45問・40分・100点（知識・技能40点／思考・判断・表現60点）**、受験番号は「学年1桁＋組1桁＋出席番号2桁」です。自校で問題を作り替えるときは、この採点設計や出題数も合わせて確認します。

### 自校版を作るときの順番

| 段階 | 先生が決めること | このコードで対応する部分 |
| --- | --- | --- |
| ① 到達目標 | 対象学年・範囲、何を知識・技能／思考・判断・表現として見るか | 問題プールの `domain`・`viewpoint`、得点配分 |
| ② 出題 | 問題数・時間・選択/入力の数、同系統問題のバリエーション | `question-bank.js`、`pool/`、ブループリント検証 |
| ③ 採点 | 正答、許容する別解、配点、結果画面で伝える助言 | `answer-key.json` を生成し、先生PCの `scoring.js` で再採点 |
| ④ 回収 | 公開ページから校内へ送れるか、通信失敗時の提出方法 | `app.js`、`server.js`、結果JSON |
| ⑤ 校務 | 名簿との照合、複数提出の扱い、成績のバックアップ | `admin.html`、`meibo.csv`、`pycbt.db` |
| ⑥ リハーサル | 生徒端末から1件送信し、先生PCで同じ記録を確認 | `local-test.html`、管理画面 |

この順番で決めると、まず「どんな力を測るか」を定め、その後に問題と保存方法を確かめられます。**出題数・40分・100点の枠自体を変える場合**は、問題ファイルだけでなく `pool/pool-engine.js`、公開側の表示・検証、サーバ側の採点・検証も一緒に変更してテストしてください。

## 2. 自校の公開ページを用意する

1. [リポジトリ](https://github.com/naturespa/pycbt)を自分のGitHubアカウントに Fork するか、コピーして新規リポジトリを作ります。生徒に公開する内容だけを登録し、実際の名簿・成績DB・結果JSONはコミットしません。
2. GitHub のリポジトリで **Settings → Pages → Build and deployment** を開き、**Deploy from a branch → `main` → `/(root)`** を選んで保存します。`index.html` はルートにあります。
3. 公開URLを確認します。リポジトリ名が `pycbt` なら通常は `https://<GitHubユーザー名>.github.io/pycbt/` です。以後、このURLを例として使います。独自ドメインや別名のリポジトリなら、その実際のURLに読み替えてください。
4. 自校の問題に変える場合は `question-bank.js` と `pool/` の各ファイルを編集します。公開する問題・正答・出典が含まれるため、公開前に問題の扱いを決めてください。問題を変更したら、リポジトリのルートで `node local-server/build-answer-key.js` を実行し、生成した `local-server/answer-key.json` を先生PCにも更新します。公開側とサーバ側の問題プールの版が違うと提出できません。

   問題プールや生徒画面を編集した後は、リポジトリのルートで次を実行します。出題、サーバ採点、送信の動作を確認できます。テストに通っても、生徒画面の文言・図表・正答の目視確認は別に行います。

   ```powershell
   node --check app.js
   node tests/pool-validation.cjs
   node tests/standalone-validation.cjs
   node local-server/scoring.test.js
   node local-server/server.test.js
   node local-server/client-flow.test.js
   ```

**他校がこのコードを Fork した場合に必要な接続先の変更**：先生PCへ置く前に `local-server/server.js` の `PAGE_ORIGIN` を `https://<GitHubユーザー名>.github.io` に、`PUBLIC_EXAM_URL` を `https://<GitHubユーザー名>.github.io/pycbt/` に変更します。前者は `/pycbt/` を付けない「オリジン」、後者は `/pycbt/` を含む「生徒用ページのURL」です。異なると生徒端末からの提出が拒否されたり、管理画面が別のURLを配布したりします。ポートは以下の手順どおり **3000** を使います。

## 3. 先生PCに成績サーバを置く

1. [Node.js の公式サイト](https://nodejs.org/en/download)からサポート中の LTS 版を導入します。新しいターミナルで `node --version` と `npm --version` を実行し、使えることを確認します。
2. 先生PCに `C:\cbt` フォルダを作ります。リポジトリの `local-server` フォルダから **`server.js`、`admin.html`、`scoring.js`、`answer-key.json` の4ファイル**をこのフォルダへコピーします。リポジトリを自校用に変更した場合は、その自校版からコピーします。
3. PowerShell またはコマンドプロンプトで次を実行します。

   ```powershell
   cd C:\cbt
   npm install express better-sqlite3 cors
   node server.js
   ```

4. 先生PCのブラウザで `http://localhost:3000/api/health` を開き、`success: true` と試験IDが返ることを確認します。次に `http://localhost:3000/admin` を開きます。管理画面は先生PCの `localhost` 専用です。生徒に `localhost:3000/admin` を案内しません。
5. 試験中はこのターミナルを閉じず、PCのスリープを避けます。成績は同じフォルダに自動作成される `pycbt.db` に入ります。`node_modules`、DB、名簿は GitHub Pages には置きません。

## 4. 校内ネットワークで接続確認する

1. 先生PCで `ipconfig` を実行し、生徒端末と通信できるネットワークの IPv4 アドレスを確認します。`127.0.0.1` は先生PC自身を指すため生徒へ配りません。
2. **先生PC**で `http://<先生PCのIPv4>:3000/api/health` を開きます。続いて **生徒端末**で同じURLを開きます。生徒端末から開けないときは、先生PCのIP、起動状態、Windowsファイアウォール、校内ネットワーク間の通信を確認します。
3. 生徒端末で `https://<GitHubユーザー名>.github.io/pycbt/local-test.html` を開き、先生PCのIPv4アドレスを入力して「接続成功」を確かめます。このテストで使ったIPは、そのブラウザの受験画面にも保存されます。
4. 公開ページから校内サーバへの通信は、学校のブラウザ設定やネットワークによって結果が変わります。**URLを開けることに加え、公開ページからの接続テストと実際の1件の成績送信まで**確認します。

## 5. 名簿を取り込む

1. 先生PCの `C:\cbt\meibo.csv` を作ります。必要な列は `受験番号,氏名` です。Excel由来の Shift_JIS、UTF-8 に対応します。

   ```csv
   受験番号,氏名
   1215,例示 一郎
   1216,例示 二郎
   ```

2. 管理画面の「名簿照合」で年度・学年を選び、**「meibo.csv を確認」**を押します。人数、追加、氏名変更、削除対象を見てから **「確認した名簿を取り込む」**を押します。選択した年度・学年の名簿だけを入れ替えます。過去の成績は消えません。
3. 名簿は先生PCのDB内で照合します。GitHubには置きません。複数学年が1ファイルにあっても学年を選んで取り込めますが、年度はCSVからは読み取らず画面で指定します。受験番号や氏名に誤りがあればCSVを直し、再度プレビューして取り込みます。

名簿はなくても成績の保存自体はできます。ただし、誰が未提出かを管理画面で照合するには名簿が必要です。

## 6. 試験IDを決めて、生徒にURLを渡す

1. 受験中の生徒がいないことを確かめ、先生PCの管理画面の **「試験ID設定」**でその回だけのID（例：`2026-term2-midterm`）を設定します。英数字・ピリオド・アンダースコア・ハイフンを使えます。この設定は先生PCのDBに保存されます。
2. 画面に表示された **「生徒用URL」**をコピーして配布します。URLには `?exam=2026-term2-midterm` のような試験IDが付きます。現在の実装では、試験ごとに GitHub 側のコードを書き換える必要はありません。
3. 生徒には「先生PCのIP、4桁受験番号、氏名を確認してから開始」と伝えます。`?exam=` がない旧URLは固定の初期IDを使うため、毎回 **管理画面が発行したURL**を配布します。試験中に試験IDを変更しないでください。

**同じ受験番号・同じブラウザ**では提出済みの再受験を防ぎ、中断した試験はそのブラウザで再開できます。別端末・別ブラウザ、ブラウザデータ消去後は同じ仕組みで一律に止められないため、再受験は管理画面の提出回数も見て判断します。

## 7. 事前リハーサルから当日の運用まで

1. テスト用の受験番号・仮の氏名で生徒端末から1件受験します。途中で提出しても構いません。生徒側の「学校サーバで再採点し、成績を保存しました」という表示を確認し、先生PCの `/admin` に **同じ試験ID・受験番号の記録**が増えたことを確認します。テスト記録は必要に応じて行の「削除」で成績一覧から外せます。
2. 成績が送れなかった場合は、生徒側の結果JSONをダウンロードして先生に渡します。**現在の管理画面には、そのJSONを取り込む機能はありません。** 画面で保存成功と表示されても、先生PCの管理画面に記録があるか確かめます。
3. 本番前に試験ID、生徒用URL、先生PCのIP、問題プールの版、1件の送信、名簿人数、スリープ状態を確認します。印刷物などで生徒に案内するURLは、最終の試験ID設定後のものにします。
4. 当日は先生PCでサーバを起動してから配布URLを開かせます。試験中は成績画面の提出人数を確認し、終了後は「名簿照合」で未提出・氏名不一致・複数提出・名簿外の提出を確認します。氏名の照合は本人確認の代わりにはなりません。
5. 成績表をクラス・試験で絞り込み、**表示中の結果をCSV出力**します。照合一覧も別のCSVで出せます。成績CSVを校務系へ移す方法や保存先は、各校の個人情報の扱いに合わせます。

## 8. バックアップ、訂正、更新

- 管理画面の **「DBをバックアップ」**で、その時点のSQLiteデータを取得します。先生PCの `C:\cbt\backups` にも保存されます。`pycbt.db` が原本です。復旧が必要なら、まずサーバを止め、バックアップを別の安全な場所に保全してから作業してください。稼働中のDBファイルだけを手でコピーするより、管理画面のバックアップを使います。
- 誤提出は成績表の該当 **記録ID** の「削除」で一覧から外せます。削除前にDBバックアップを作り、削除履歴に1件を残します。誤って削除した場合は「削除履歴・復元」でその記録だけを戻せます。**復元できるようにするため、削除した個人データは校内DBとバックアップに残ります。** 完全消去とは異なります。
- 新しい版の `server.js` と `admin.html` を反映するときは `Ctrl+C` でサーバを止め、DBをバックアップし、必要なファイルを上書きして再起動します。**`pycbt.db` と `meibo.csv` を上書きしません。** 問題を変えた場合は `scoring.js`・`answer-key.json` と公開側の問題プールの整合を取り直します。

## 困ったときの切り分け

| 症状 | 最初に確認すること |
| --- | --- |
| `Cannot GET /admin` | 生徒ページではなく先生PCの `http://localhost:3000/admin` を開いたか、`C:\cbt\server.js` を最新版にして再起動したか |
| 管理画面に `Unexpected token '<'` | 画面だけ新しく、実行中の `server.js` が古い可能性。両ファイルを同じ版にしてサーバを再起動 |
| `meibo.csv` が見つからない | `server.js` と同じ `C:\cbt` に置いたか。CSVの見出し、学年、重複番号もプレビューで確認 |
| 生徒からサーバに届かない | 先生PC・生徒PCの `/api/health`、`local-test.html`、IP、ポート3000、ファイアウォール、GitHub PagesのURLと `PAGE_ORIGIN` |
| 試験IDが異なる | 管理画面で表示されたURL（`?exam=`付き）を配ったか。試験中にIDを切り替えていないか |
| 問題プールの版が異なる | 公開ファイルと先生PCの `answer-key.json` が同じ編集内容から作られているか |
| 「保存」と出たが成績が見えない | 管理画面の試験・クラスの絞り込み、最新記録のみの設定、記録ID、削除履歴を確認 |

## この構成を使う範囲

GitHub Pages には成績DBや名簿を置かず、先生PCで受信・再採点・管理します。公開した問題・正答を秘匿できないこと、受験者の本人確認がないこと、先生PCの稼働と校内通信に依存することを踏まえ、学校の試験要件に合うか確認してから使用します。個々の点数や名簿を公開リポジトリの Issue、スクリーンショット、問題報告などへ貼り付けないでください。
