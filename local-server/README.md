# pycbt 校内成績サーバ

`server.js`、`admin.html`、`scoring.js`、`answer-key.json` の **4ファイル**を先生PCの `C:\cbt` にコピーします。成績データ `pycbt.db` は GitHub には置きません。

## 現行サーバからの更新

1. 実行中の `node server.js` を `Ctrl+C` で終了します。
2. `C:\cbt\pycbt.db` を別の安全な場所へバックアップします。終了後に `pycbt.db-wal` と `pycbt.db-shm` が残っている場合は、それらも一緒にバックアップします。
3. このフォルダの `server.js`、`admin.html`、`scoring.js`、`answer-key.json` を `C:\cbt` にコピーします。既存の `server.js` は上書きし、`pycbt.db` は上書きしません。
4. 未導入の場合だけ `cd C:\cbt`、`npm install express better-sqlite3 cors` を実行します。
5. `cd C:\cbt`、`node server.js` で起動します。
6. **先生PCで** `http://localhost:3000/admin` を開きます。旧成績が「従来記録」、新規成績が試験IDごとに表示されます。CSVとDBバックアップを試します。

受験画面では、先生PCのIPv4アドレスを各端末で一度入力します。端末内に保存されるため、次回からは入力済みになります。`local-test.html` で接続に成功すると、その端末では受験画面にもIPが引き継がれます。先生PCのIPが変わった場合は、各端末で入力し直してください。`/api/health` はLANから接続確認できます。

今回は `practice-2026-09-25` を試験IDとして設定しています。**本番の前には**公開側 `app.js` の `EXAM_ID` とサーバ側 `server.js` の `ACTIVE_EXAM_ID` を同じ新しいID（例：`2026-term2-midterm`）へ変更し、サーバを再起動してください。試験中にIDを切り替えないでください。過去の成績は残り、管理画面で試験ごとに切り替えられます。

## 管理画面

- クラスで絞り込んで提出状況を確認できます。名簿を未登録のため「未提出者」は表示されません。
- 標準では試験ごと・受験番号ごとに最後に保存した1件を表示します。チェックを外すと過去の記録も表示します。
- 現在の試験・クラス・表示条件を反映したCSVを出力します。A～Fの得点は保存済みの解答から集計します。
- 「DBをバックアップ」を押すと、SQLiteのスナップショットをダウンロードし、先生PCの `C:\cbt\backups` にも作成します。バックアップ先の空き容量を確認し、不要な古いコピーは適切に整理してください。
- 管理画面、成績一覧API、CSV出力は先生PCの `localhost` からのみ利用できます。生徒PCからの成績提出と接続確認は継続します。

## 運用上の範囲

新しい成績はサーバが公開問題プールから生成した正答データで再採点し、端末から送られた得点と食い違うと「要確認」と表示します。旧成績は再採点済みとみなしません。生徒本人であることの確認や受験番号のなりすまし防止は別途必要です。成績の外部公開や、校内の別端末から管理画面を開く運用には対応していません。

問題プールを編集したら、リポジトリのルートで `node local-server/build-answer-key.js` を実行し、更新された `answer-key.json` をサーバにもコピーしてください。公開側とサーバ側の問題プールの版が合わないと、提出は失敗し、端末に結果JSONが残ります。
